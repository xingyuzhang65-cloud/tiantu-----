## 1. 背景与目标

### 1.1 背景

销售人员在正式开户前，需要先维护尚未完成资质提交的潜在客户，并持续跟进询价情况。当前系统已有正式“客户”页面，但缺少独立的意向客户承接、筛选和转开户入口。

### 1.2 产品目标

1. 建立独立的意向客户台账，支持新增、编辑、查询、导出和操作追溯。
2. 在意向客户详情中集中查看询价单号、询价渠道、报价状态、报价时间和报价结果。
3. 通过“发起开户”将意向客户的基础信息带入正式客户新建流程，减少重复录入。
4. 在正式客户查看/编辑页面继续查看客户自身的询价记录，保证开户后的业务跟进连续性。

### 1.3 本期范围

**包含：**

- 意向客户菜单、列表及查询条件；
- 新增、编辑意向客户；
- 询价记录只读展示；
- 报价结果单行截断与悬停查看全文；
- 当前筛选结果导出；
- 意向客户操作日志；
- 从意向客户发起正式客户开户及字段回填；
- 正式客户查看/编辑页面的询价记录展示。

**不包含或需后续确认：**

- 在意向客户页面手动新增、绑定、编辑或删除询价记录；
- 后端持久化、接口权限和真实组织人员数据；
- 开户成功后自动改变意向客户状态或自动归档；
- 意向客户询价记录自动迁移到正式客户；
- 真实的表格列显隐/排序配置、分页和批量操作。

## 2. 角色与入口

### 2.1 使用角色

| 角色 | 主要操作 |
| --- | --- |
| 业务人员 | 新增/编辑意向客户、查询、查看询价、发起开户 |
| 跟单/运营人员 | 查看意向客户及询价记录、导出数据、查看日志 |
| 管理员 | 以上操作及后续权限配置 |

具体角色权限以系统统一权限中心为准；当前前端为演示数据，尚未接入权限接口。

### 2.2 菜单入口

- 路径：`管理 / 账号设置 / 意向客户`。
- “意向客户”位于“客户”菜单上方。
- 点击菜单后进入意向客户列表页；页面标题为“意向客户”，辅助说明为“管理意向客户及开户资料”。

## 3. 业务流程

### 3.1 主流程

```text
进入意向客户列表
        ↓
查询/筛选意向客户
        ↓
查看询价记录 或 编辑意向客户
        ↓
点击“发起开户”
        ↓
切换至客户页并打开“新建客户”抽屉
        ↓
完善正式客户资料并保存
        ↓
正式客户进入客户列表
```

### 3.2 询价记录查看流程

```text
意向客户列表 → 询价记录 → 只读记录表
                                   └─ 报价结果默认一行
                                      鼠标移入显示完整内容
                                      鼠标移出隐藏
```

## 5. 意向客户列表

### 5.1 列表字段

列表共 11 列，顺序固定如下：

| 序号 | 字段 | 规则 |
| --- | --- | --- |
| 1 | 客户编码 | 系统生成，不可在编辑弹窗中修改 |
| 2 | 公司名称 | 意向客户公司名称 |
| 3 | 业务代表 | 负责业务人员 |
| 4 | 跟单代表 | 负责跟进人员 |
| 5 | 询价单号 | 当前客户最新询价记录的询价单号 |
| 6 | 询价渠道 | 最新询价记录的渠道 |
| 7 | 最近询价时间 | 最新询价时间，列表显示 `MM-DD HH:mm` |
| 8 | 询价次数 | 当前客户累计询价次数 |
| 9 | 创建时间 | 列表显示 `MM-DD` |
| 10 | 创建人 | 创建操作人 |
| 11 | 操作 | 询价记录、编辑、发起开户 |

最新询价记录按 `inquiryTime` 倒序确定；没有询价记录的字段显示 `-`。列表表头吸顶，内容区支持横向和纵向滚动，行悬停高亮。

### 5.2 查询条件

| 条件 | 控件 | 匹配规则 |
| --- | --- | --- |
| 客户编码 | 文本框 | 去首尾空格、忽略大小写、包含匹配 |
| 公司名称 | 文本框 | 去首尾空格、包含匹配 |
| 业务代表 | 文本框 | 去首尾空格、包含匹配 |
| 跟单代表 | 文本框 | 去首尾空格、包含匹配 |
| 询价单号 | 文本框 | 去首尾空格、忽略大小写；当前版本匹配最新询价 |
| 询价渠道 | 下拉框 | 全部、微信询价、电话询价、邮件询价、官网询价、线下询价；当前版本匹配最新询价 |
| 询价时间 | 起止日期时间 | 包含边界，当前版本比较最新询价时间 |

交互规则：

- 点击“查询”后才应用查询草稿条件。
- 文本框按 Enter 等同点击“查询”。
- 点击“重置”同时清空输入和已应用条件，恢复全量列表。
- 当前版本未限制开始时间必须早于结束时间；后端实现时应补充校验和明确提示。
- 结果区显示“共 N 条”；无结果显示“暂无符合条件的意向客户”。

## 6. 新增与编辑意向客户

### 6.1 表单字段

| 字段 | 控件 | 必填 | 选项/规则 |
| --- | --- | --- | --- |
| 公司名称 | 文本框 | 是 | 保存时去首尾空格 |
| 业务代表 | 下拉单选 | 是 | 天期、天金、天成、天宇、天气、天明 |
| 跟单代表 | 下拉单选 | 是 | 天睿、天全、天旺、天朗 |

新增和编辑均不允许人工编辑客户编码；编辑时仅回填并修改上述三项。

### 6.2 新增规则

1. 校验顺序为公司名称、业务代表、跟单代表；缺失时阻止保存并提示。
2. 客户编码由系统自动生成：`SZ` + 六位数字；数字部分取现有编码最大值加一，不足六位左侧补零。
3. 新增记录插入列表首位，询价次数初始化为 `0`，最近询价时间为空。
4. 创建时间取当前时间，创建人取当前登录人；演示版默认显示“天朗”。
5. 保存成功后记录“新增”日志并显示成功提示。
6. 点击取消、关闭按钮或遮罩区域关闭弹窗；关闭时清空新增草稿，不保留未保存内容。

### 6.3 编辑规则

1. 打开编辑弹窗时回填当前意向客户数据。
2. 客户编码、询价记录、创建时间和创建人不可编辑。
3. 三个业务字段按新增规则校验和 trim。
4. 保存成功后局部更新列表，记录“编辑”日志并显示成功提示。
5. 取消、关闭或点击遮罩时放弃草稿，不修改原数据。

## 7. 询价记录

### 7.1 入口与模式

- 从列表操作列点击“询价记录”打开只读弹窗。
- 弹窗顶部展示公司名称和意向客户编码。
- 当前版本删除“手动绑定询价单号”及其相关新增、编辑、删除入口。
- 询价记录仅用于查看；无记录时显示“暂无询价记录”。

### 7.2 展示字段与顺序

表格固定展示以下 5 列：

1. 询价单号
2. 询价渠道
3. 是否已报价
4. 报价时间
5. 报价结果

数据模型中的“询价时间”仍保留，用于最新询价计算和筛选，但不在记录表中展示。

### 7.3 报价结果展示

报价结果可能包含多条线路及价格，示例内容为：

```text
加拿大加东直航30日达  ¥31.9/KG
加拿大加东直航33日达  ¥31.3/KG
加东-美转加25日达      ¥33.8/KG
加东-美转加20日达      ¥34.6/KG
加东-美转加19日达      ¥35.8/KG
```

交互要求：

- 列表单元格默认只显示一行，超出宽度使用省略号。
- 鼠标移入报价结果时，在页面浮层中显示全部线路和价格，线路与价格左右对齐。
- 鼠标移出后浮层隐藏。
- 键盘聚焦单元格时同样可查看完整内容，失焦后隐藏。
- 浮层不得被表格滚动容器裁切；视口底部空间不足时向上显示。
- 未报价记录的报价时间和报价结果显示 `-`。

### 7.4 数据与排序

- 记录通过 `customerId` 关联客户。
- 询价记录表按数据源顺序展示；列表中的“最新询价”按询价时间倒序计算。
- 当前前端使用演示种子数据；生产环境应由询价业务数据源提供，不应依赖页面内存生成。

## 8. 导出

### 8.1 导出范围

导出当前筛选后的意向客户结果，不受分页影响（当前无分页）。没有筛选结果时仍导出表头文件。

### 8.2 CSV 字段

| 顺序 | 字段 |
| --- | --- |
| 1 | 客户编码 |
| 2 | 公司名称 |
| 3 | 业务代表 |
| 4 | 跟单代表 |
| 5 | 询价单号 |
| 6 | 询价渠道 |
| 7 | 最近询价时间 |
| 8 | 询价次数 |
| 9 | 创建时间 |
| 10 | 创建人 |

每个客户只导出最新询价记录；无值使用 `-`。文件名为 `意向客户列表.csv`，使用 UTF-8 BOM，字段值需正确转义双引号，确保中文 Excel 可正常打开。

导出完成后记录“导出 N 条意向客户数据”日志并显示成功提示。

## 9. 操作日志

日志弹窗展示：时间、操作人、动作、内容；新日志置顶，内容区可滚动。

当前需要记录的动作：

- 新增意向客户；
- 编辑意向客户；
- 导出当前列表。

查询、重置、查看询价记录、发起开户和列设置入口当前不记日志。生产环境应使用登录态操作人，不使用前端硬编码。

## 10. 与客户页面的关联

### 10.1 发起开户流程

1. 用户在意向客户列表点击“发起开户”。
2. 系统生成一次性 `CustomerCreateSeed`，并切换到“客户”页签；客户页签未打开时加入已打开页签。
3. 客户页进入“新建客户”模式，清空当前客户、联系人和营业执照状态，并自动打开新建客户右侧抽屉。
4. 客户页消费开户种子后通知父级清空种子；`requestId` 用于防止重复初始化。
5. 用户完善正式客户资料并保存，正式客户插入客户列表首位。

### 10.2 字段回填

| 意向客户字段 | 客户页字段 | 回填规则 |
| --- | --- | --- |
| 公司名称 | 客户名称 | 自动带入，可继续修改 |
| 公司名称 | 认证资料 → 公司名 | 自动带入，可继续修改 |
| 业务代表 | 销售代表 | 自动带入，可继续修改 |
| 跟单代表 | 跟单代表 | 有值时带入，无值则为空 |
| 意向客户编码 | 备注 | 自动生成 `由意向客户 {客户编码} 发起开户` |

以下信息当前不自动带入：联系人、联系方式、营业执照、询价记录、意向客户状态和其他扩展字段。

### 10.3 客户抽屉模式

| 客户页面模式 | 是否展示询价记录 | 是否允许新增/绑定询价 |
| --- | --- | --- |
| 新建客户 | 否 | 否 |
| 查看客户 | 是 | 否 |
| 编辑客户 | 是 | 否 |

查看和编辑模式只展示当前正式客户 `customerId` 对应的记录，不得串显示其他客户记录。询价记录字段顺序及报价结果悬浮交互与意向客户页面一致。

### 10.4 正式客户保存规则

当前前端实现的最低校验为：

- 客户名称为空时不允许保存；
- 手工填写的客户编码与已有编码重复时不允许保存；
- 客户编码为空时按 `SZ` + 六位数字规则自动生成；
- 保存成功后正式客户状态默认为“启用”，插入客户列表首位。

产品正式上线前，应补齐界面星号字段的后端必填校验，并明确客户编码、统一社会信用代码等唯一性规则。

### 10.5 当前关联边界

- 开户成功后不会自动把意向客户标记为“已开户”、归档或从意向客户列表移除。
- 意向客户询价记录不会自动迁移到新正式客户。
- 正式客户目前仅通过备注文本保留意向客户编码，没有独立的来源关联字段。
- 意向客户和正式客户当前各自使用页面内存中的演示询价数据，尚未与真实询价列表建立共享数据源。

## 11. 非功能要求

1. **可用性：** 弹窗支持关闭按钮、取消按钮和点击遮罩关闭；保存失败时保留用户输入。
2. **可访问性：** 关键操作可通过键盘完成；报价结果浮层支持键盘聚焦；文本截断内容不能只依赖颜色表达。
3. **响应式：** 列表在窄屏下允许横向滚动；询价弹窗内容超出视口时允许纵向滚动；悬浮报价浮层不得超出视口。
4. **数据安全：** 导出按当前用户权限控制；客户和询价数据按客户 ID 隔离；后端应进行参数校验和越权校验。
5. **一致性：** 意向客户页和客户页的询价字段顺序、空值显示和报价结果展示方式保持一致。
6. **性能：** 列表查询、弹窗打开和浮层展示不应阻塞主页面；大数据量场景需采用分页或虚拟滚动。

## 13. 建议接口与后端落地

前端当前使用 React 内存状态和演示种子数据；正式上线建议提供以下接口：

| 接口 | 用途 |
| --- | --- |
| `GET /intended-customers` | 分页查询意向客户及最新询价摘要 |
| `POST /intended-customers` | 新增意向客户 |
| `PATCH /intended-customers/{id}` | 编辑意向客户 |
| `GET /intended-customers/{id}/inquiries` | 查询意向客户询价记录 |
| `GET /intended-customers/{id}/logs` | 查询操作日志 |
| `GET /customers/{id}/inquiries` | 查询正式客户询价记录 |
| `POST /customers` | 创建正式客户，支持 `sourceIntendedCustomerId` 和幂等键 |
| `GET /inquiry-records/{id}/quote-options` | 查询真实报价线路与价格明细 |

建议正式客户表保存独立的 `sourceIntendedCustomerId`，开户成功后由服务端事务决定意向客户状态（保留、已转化或归档），并明确询价记录是否迁移或共享。

## 14. 待确认事项与后续迭代

1. 开户成功后意向客户的状态和列表表现：保留、标记“已开户”还是自动归档。
2. 正式客户与意向客户是否建立独立来源关联字段，而不只在备注中保存编码。
3. 询价记录由哪个真实业务系统提供，是否需要自动同步报价线路和价格。
4. 查询询价单号/渠道/时间时，匹配最新记录还是任意历史记录。
5. 是否开放询价记录作废、删除或权限控制；当前明确不开放手动绑定。
6. 业务代表、跟单代表、操作人是否改为从组织架构和登录态动态获取。
7. 是否补充分页、排序、批量操作、真实列设置和权限矩阵。
8. 客户新建页面所有带星号字段的实际校验规则及后端唯一性校验。
9. 时间范围边界、开始时间晚于结束时间、时区和秒级精度规则。
10. CSV 导出是否需要增加报价状态、报价时间和报价结果字段。
